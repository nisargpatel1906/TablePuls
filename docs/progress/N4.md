# Stage N4 Report — Menu Management, Validated Media Pipeline & Table QR Backend

## Summary
- Implemented server-validated WebP media pipeline (`backend/app/services/media.py`):
  - Enforces 5 MB cap (`413 PAYLOAD_TOO_LARGE`), strict magic-byte sniffing (`JPEG`/`PNG`/`WebP`), blocks SVG/XML/polyglot payloads (`400 UNSUPPORTED_MEDIA_TYPE`), enforces Pillow `MAX_IMAGE_PIXELS = 25_000_000` & `>= 200x200` min dimensions, strips EXIF/ICC metadata, outputs `800px` full + `320px` thumbnail WebPs via `0600` atomic temp files, deduplicates per venue by SHA-256, and serves `/media/menu/{venue_id}/{filename}` with sandbox CSP & `nosniff`.
- Implemented timezone-aware menu schedule evaluator (`backend/app/services/menu_schedule.py`) supporting daytime and overnight windows (`22:00`–`02:00`).
- Implemented Menu Management APIs (`backend/app/api/menus_admin.py` + `backend/app/schemas/menus_qr.py`):
  - `API-026`–`API-031`: Menus (draft/publish validation gate `422 MENU_NOT_PUBLISHABLE`, cascade soft-delete), venue menu settings (branding, `allow_host_menu_availability`, `OWNER`-only currency lock `409 CURRENCY_LOCKED`), ordered categories (`409 CATEGORY_NOT_EMPTY` guard + atomic reorder), menu items (minor-unit prices, dietary/allergen validation, variants, duplicate, optimistic locking `409 VERSION_CONFLICT`, UTF-8 BOM formula-safe CSV export), 1-tap & bulk Quick-86 availability toggles, and media upload/delete (`409 MEDIA_IN_USE`).
- Implemented Offline QR Export & Lifecycle APIs (`backend/app/api/qr_admin.py` + `backend/app/services/qr_export.py`):
  - `API-032`–`API-034`: QR list + 7d scan stats, atomic QR regeneration with optional grace window (`COMPROMISED` forces immediate revocation), `end-grace`, 15-min HMAC preview link, offline `segno` SVG/PNG (plain + framed card with anti-quishing short domain), `reportlab` cut-guided multi-table PDF export (`A4_4UP`, `A4_6UP`, `LETTER_4UP`), and background expiration task (`expire_grace_qr_codes_once`).
